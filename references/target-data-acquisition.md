# 目标数据获取

请求者仅提供姓名、精确 ITRA Runner ID 和目标赛事；公开 URL、路线文件、CP 表、图片、PDF、GPX 与历史均是智能体工作。

## 必需顺序

1. 建立新的不可变请求并进行新鲜 ITRA 抓取；精确 Runner ID 是身份关卡。
2. 从官方赛事/报名页解析赛事年份与精确组别；裸赛事名对应多个有效组别时，仅询问组别选择。
3. 搜索并回执每条必需通道：官方赛事/规程、报名/组别页、路线/路书/GPX/附件、CP/补给/关门、官方通知/社媒、计时/追踪、历史路线/成绩。
4. 下载每个发现附件；保存原始字节、URL、抓取时间、响应/错误、内容类型、SHA-256 与目标绑定。
5. 确定性解析 HTML 表和 GPX；图像/PDF 文本不足时必须视觉检查，并将结构化转录绑定原始 SHA-256。提取 CP 名称、分段/累计距离、分段/累计爬升下降、起跑/关门、补给、装备、支持限制、路线版本、年份和组别。
6. 先对齐当年官方来源；完整搜索后仍不可用时，可使用最新同赛事/同组官方历史路线作为 `official_historical_reference`，并对比总量、端点、版本线索与已知变化。
7. 第三方/计时/跑者材料只能做显式交叉核验，绝不可提升为官方事实。

## 状态规则

- `checked_not_confirmed`：已获取并解析，但年份/组别适用性未解决或来源冲突。
- `attachment_not_acquired`：发现附件但未取得字节。
- `attachment_parse_failed`：已取得字节但未形成可靠结构化解析。
- `officially_not_published`：仅当同年同组官方声明支持未发布。

已知含路线/CP 材料的附件仍未获取或未解析时，不得产出完成报告；继续自主兜底搜索。所有允许路径失败时，报告已尝试来源、精确错误、历史参考可用性和下一自动重抓动作，不把工作交回请求者。

## 可执行策略报告的 CP 证据门槛

1. 优先同年、精确组别官方结构化 CP/补给/关门表（或官方 GPX）；6.1 和 6.2 仅以全部官方行作为分段基准。
2. 没有该表时，必须发现、下载并视觉转录同年、精确组别官方赛道图、路书、PDF 或图片。每个转录 CP 行保留 `source_url`、`retrieved_at`、`raw_sha256`、`applicable_year`、`applicable_group`、`parser_method` 与视觉转录备注/置信度。
3. 路线/CP 附件处于 `attachment_discovered`、`attachment_not_acquired` 或 `attachment_parse_failed` 是硬阻断；不得称为 `checked_not_confirmed`，`terminal_report_allowed` 保持 `false`。
4. 仅起点+终点、行动锚点及来源完全为 `derived` 的行不是 CP 证据，绝不得满足本门槛。

仅在门槛通过后，才可渲染可执行的 `6.1 全段总览表`、`6.2 逐段战术详解`、CP 到达/离站执行预算或余量计算。历史行可用于准备确认单，但不能解锁完整目标年策略。门槛不能通过时，仅生成 `赛道资料待补全确认单`：已尝试来源、附件状态/错误、已知事实和下一自动抓取动作；不得提供 CP 时刻表、逐段战术或最终 PDF。
